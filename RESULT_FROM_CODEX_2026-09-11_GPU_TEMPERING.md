# Рациональный поиск на Radeon: результат сравнительного эксперимента

2026-09-11. **Обмен состояниями не показал преимущества:** 12 побед, 12 поражений, 6 ничьих в 30 парных запусках. Полезный результат — сокращение задачи с четырёх рациональных параметров до перебора двух с оптимальным подбором оставшихся в конечной таблице. Это классические вычисления. Точного магического квадрата не найдено.

## Постановка и границы опыта

Формулы приведены в IDEA.md. t=p/q, gcd(p,q)=1, 0<|p|<q≤H. Отрицательные параметры дают положительные u, положительные — отрицательные. Повторяющиеся рациональные значения u удалены. H=24,64,128 дают соответственно 242,1694,6716 различных значений u. Нулевые u исключены; при оценке исключены совпадения |u_i|=|u_j|. Клетки положительны и различны. Никакого дополнительного минимального промежутка между клетками не навязывали.

Энергия E=(u3-u1-u2)²+(u4-2u1-u2)². Для фиксированных u1,u2 надо приблизить два заданных числа u1+u2 и 2u1+u2 значениями u3,u4. Из списка кандидатов исключаются абсолютные значения u1,u2. Достаточно трёх ближайших кандидатов для каждой цели: после фиксации второго элемента запрещённое абсолютное значение удаляет не более двух значений (+u и −u). Если оптимальный первый элемент находится дальше первых трёх, хотя бы один из этих трёх допустим и имеет не большую ошибку. Поэтому минимум по 3×3 совместным вариантам достигает минимума при фиксированной паре. Это сокращение имеет точное математическое обоснование; GPU реализует сравнения в double.

H ограничивает параметры окружности, **не общий знаменатель девяти корней**. Опыт не является полным перебором всех магических квадратов до центрального корня H. Увеличение общего знаменателя само по себе не считается прогрессом к точному решению.

## Что сравнивалось

- Независимые цепочки: 4096 цепочек, температуры по 8 уровням от 10⁻¹⁴ до 10⁻².
- Обмен: тот же набор цепочек, температур и локальных предложений, плюс обмен соседними температурами через 32 шага, по правилу Метрополиса. Это parallel tempering, без симуляции кубитов.
- 512 предложений на цепочку; **2 097 152 предложения на запуск**. 30 общих начальных seed: 20260911–20260940. Порядок двух методов чередовали. Все параметры опыта зафиксированы до расширения с 5 до 30 пар; после просмотра результатов настройки не подбирали.
- Предложение меняет один из двух индексов; примерно 1/8 — глобальная случайная замена, прочие — шаги по упорядоченной таблице. Противоположные пары остаются рациональными квадратами.
- Контроль: полный перебор упорядоченных пар u1,u2 в каждой из трёх таблиц.

Основной бюджет — одинаковое число предложений. Реальное время измеряли; жёсткого обрыва по одинаковому wall-clock сроку не применяли. CPU-проверка и построение таблиц не включены в времена поиска. Полный process_ms включает запуск процесса и вывод, но не компиляцию и последующий независимый аудит.

Для H=128 это 45 104 656 пар (45 091 224 после исключения совпадающих абсолютных значений). Полный процесс занял 163.80 мс; непосредственно вычислительный вызов — 73.75 мс. Это один измеренный прогон, не обещание устойчивой скорости длительного поиска. Перебор получил лучший наблюдённый результат, но потратил больше времени и предложений, чем один короткий запуск отжига; универсального преимущества по скорости здесь не утверждаем.

## Лучший проверенный кандидат H=128

Параметры t: 2/11, -20/123, 34/35, 16/79.

Положительные рациональные корни клеток:

    73/125  19649/15529  2449/2381
    8513/6497  1  3457/6497
    2311/2381  9809/15529  161/125

- Энергия: 6.36536844071e-15; точное значение сохранено в verified.json.
- Максимальное отклонение суммы линии от 3: 1.12676280427e-07 = 421305425904/3739078218647640625.
- Минимальный промежуток между клетками: 0.05793439. Приближение не получено слиянием клеток в этом кандидате.
- Общий центральный корень при приведении к целым: **30027955606625**. Это существенное увеличение высоты: малая нормированная невязка не означает малую целочисленную ошибку.

Кандидат не магический квадрат. По величине нормированной ошибки он также не улучшает прежний опыт округления (там ≈7.99×10⁻⁸); преимущество новой постановки — точное сохранение квадратности клеток и четырёх из восьми магических сумм на каждом шаге.

## Проверки и доказательный статус

- Для H=6 полный точный перебор u3,u4 независимо подтвердил оптимальность выбора трёх ближайших на всех 224 допустимых парах u1,u2.
- Для H=24 полный CPU-перебор пар с рациональными вычислениями дал точно ту же минимальную энергию, что GPU. 58 564 пары; результат exact_oracle.json. Доказательство сокращения к трём ближайшим приведено выше.
- Для всех 258,048 сохранённых строк (уникальных реконструкций 102,826) на CPU проверены рациональная квадратность девяти клеток, положительность, различность, все восемь невязок и согласованность энергии GPU с точным значением. Расхождений 0.
- Дополнительно GPU сохраняет все посещённые кандидаты с E<10⁻²⁴; таких кандидатов 0, переполнения буфера нет. Это не замена независимому повторению всего большого поиска точной арифметикой.
- Полные большие диапазоны H=64,128 повторно точными рациональными вычислениями на CPU не перебирались. Для них не заявляется формальный сертификат отсутствия решения. На H=128 лучший GPU-кандидат перепроверен точно, но точность всей глобальной сортировки энергий отдельно не сертифицирована.
- Ни общего доказательства несуществования, ни нового точного квадрата, ни квантового ускорения этот опыт не дал.

## Решение по дальнейшей работе

Не увеличивать расходы на обмен состояниями по одному первоначально удачному тесту: устойчивого эффекта нет. Сохранить рациональную таблицу, подбор двух параметров и точную проверку как рабочую основу GPU-ветки. Следующее содержательное расширение — поиск с учётом высоты общего знаменателя и точных модульных условий. Доказательную ветку Richelot/Чабо продолжать отдельно.

    python research/quantum_inspired/scripts/verify.py
    python research/quantum_inspired/scripts/exact_oracle.py
    python research/quantum_inspired/scripts/report.py

GPU-программе нужен доступ к устройству. run_benchmark.py сохраняет существующие запуски; для нового эксперимента сначала выбрать отдельную папку результатов или архивировать текущую. Исходные файлы других сессий не менялись.
