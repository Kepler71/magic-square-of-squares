## 1. Ветка прямого поиска полного магического квадрата

В параметризации из HANDOFF магичность эквивалентна `δ=2x+y+z=0`. Для прямого поиска полного квадрата можно сразу подставить `z=−2x−y`:

```
c+x        c+y      c−x−y
c−2x−y      c       c+2x+y
c+x+y      c−y      c−x
```

Все строки, столбцы и диагонали тогда имеют сумму 3c тождественно. При `c=m²` остаётся потребовать квадратность четырёх противоположных пар с разностями `x,y,x+y,2x+y`. Это убирает одну переменную до перебора. Для исследования полумагических точек с δ≠0 такое ограничение не применяется.

Положительную невырожденную конфигурацию можно привести симметриями квадрата к `x>0`, `y>0`, `x≠y`, `2x+y<c`. Эти условия удобно применять при перечислении кандидатов; модульные совпадения сами по себе не являются совпадениями целых клеток и не должны отбрасываться как вырожденность.

Для модуля N обозначим

    D_N(c) = {d mod N : c+d и c−d — квадратичные вычеты}.

Допустимые пары остатков определяются точно условием

    x, y, x+y, 2x+y ∈ D_N(c).

Уже известная идея модульного сита превращается в генератор допустимых классов остатков: заранее построить таблицы, соединить их китайской теоремой об остатках, затем перебирать точки соответствующих решёток. GPU не обязан проходить каждый узел плотной сетки.

## 2. Почему исходные модули дают всего 125–1625 шаблонов

Достаточно искать примитивные целочисленные квадраты. Их центральный корень m нечётен и не делится на простые p≡3 mod 4. Если такой p делит m, равенство каждой противоположной пары `a²+b²=2m²` вынуждает p делить все девять корней; примитивность нарушена. При чётном m аналогичный вывод получается по модулю 4.

Следовательно, для примитивного поиска m взаимно прост с 2,3,7,11. При нечётном m маска исходного модуля 64 в точности требует `x=y=0 mod 8`; при 3∤m часть маски modulo 9 в точности требует `x=y=0 mod 3`. Это проверено для всех соответствующих остатков m, не только одного центра.

Поэтому маски `(64,63,65,11)` эквивалентны маскам

    (8,3,7,5,13,11), общий период L=120120.

Для фиксированного m допустимая пара задаётся одним из шаблонов `(r_x,r_y)`:

    x = r_x + L·i,   y = r_y + L·j.

| gcd(m,65) | Число шаблонов пар modulo L |
|---:|---:|
| 1 | 125 |
| 5 | 625 |
| 13 | 325 |
| 65 | 1625 |

Количество зависит от указанной группы, а конкретные остатки зависят от m. Нельзя подставлять таблицу для m=1 при произвольном центре без пересчёта/правильного масштабирования. В частности, центры, делящиеся на 5 или 13, не отбрасываются.

Для gcd(m,65)=1 это 125 пар из L²=14 428 814 400, то есть примерно одна из 115 миллионов сырых пар остатков. **Это плотность необходимой маски, а не измеренный коэффициент ускорения программы.** Большая часть эффекта включает простые условия делимости: при 5∤m имеем x,y кратные 120. После деления на 120 остаётся 125 шаблонов modulo 1001, то есть 125 пар из 1 002 001.

`scripts/modular_grid.py` строит таблицы для произвольного допустимого m и проверяет их независимым полным перебором квадратности девяти клеток по каждому исходному модулю. Результат и таблицы для четырёх представительных центров сохранены в `results/modular_grid.json`. Прохождение маски не означает, что девять целых значений — квадраты.

## 3. Реальная проверка на Radeon RX 7900 XTX

На ПК обнаружены `/opt/rocm/bin/hipcc`, `rocminfo`, `clinfo`; ROCm подтвердил GPU **AMD Radeon RX 7900 XTX, gfx1100**. Эта модель также указана в [официальной таблице ROCm](https://rocm.docs.amd.com/projects/install-on-linux/en/latest/reference/system-requirements.html). Для прототипа использован HIP/C++, цель компиляции gfx1100.

Проверен центр

    m=10000000001,
    c=m²=100000000020000000001 > 2⁶⁴.

GPU нигде не вычисляет c в 64 битах. Для каждого малого модуля p он вычисляет `(m mod p)² mod p`, затем остатки восьми соседних клеток. Все эти промежуточные произведения малы. Большие числа используются только в независимой CPU-проверке на 128-битных целых.

Прототип генерирует кандидатов по 125 шаблонам и применяет дополнительные модули `(17,19,23,29,31,37)`.

Фактический результат последнего запуска:

- Всего проверено 1 048 576 входов, включая один специально добавленный положительный модульный контроль вне обычного блока сетки.
- Обычный блок: 1 048 575 входов, выживших после дополнительных модулей — 0.
- Положительный контроль принят. Это кандидат, проходящий конгруэнции, а не известный магический квадрат.
- Расхождений с независимым CPU-вычислением девяти фактических целых значений — **0**.
- Один измеренный GPU-вызов: **0,280091 мс**, без выделения памяти, копирований, запуска процесса и проверки CPU.
- Независимая CPU-проверка всех входов: около **9,85 мс**. Она выполняет другую, более тяжёлую арифметику, поэтому эти числа не являются честным сравнением оптимизированных CPU- и GPU-реализаций.

Это короткий тест корректности, а не исследование скорости на длительном поиске. Он не проверял полную целочисленную квадратность выживших, поскольку среди обычных входов выживших не было. Нулевой результат в этом небольшом блоке не означает отсутствия решения при данном центре.

## 4. Что имеет смысл делать дальше

1. Если нужна именно GPU-ветка полного магического квадрата, использовать готовые разреженные шаблоны, оставив δ тождественно нулевым.
2. Генерировать только примитивные допустимые центры; корректно обрабатывать делимость на 5 и 13. Не превращать маску для единичного центра в универсальную без масштабирования.
3. Добавлять модульные фильтры по измеренной полезности; собирать статистику выживших, копирований и полного времени пакета, а не только времени ядра.
4. Выживших проверять точно на CPU: девять квадратов, положительность, различность, примитивность и суммы. Для значений порядка 10²⁰ арифметики int64 недостаточно; текущая схема избегает проблемы на GPU с помощью остатков.
5. Геометрическую решётку Морделла—Вейля вести отдельно: она может дать доказательные ограничения, которых конечный GPU-перебор сам по себе не даёт.

Для нашей фиксированной ветки s=1/5 уже имеется более специальная редукция к двум последовательностям ранга 1 и условиям lifting. Общая сетка полезнее как отдельный поиск по разным центрам, чем как замена этой редукции.
