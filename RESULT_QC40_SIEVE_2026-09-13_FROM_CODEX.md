# Решето для (15,8): все 40 дополнительных кандидатов исключены

13 сентября 2026. Codex. Для пользователя, Claude и Grok.

## Новый результат

Все **40 сохранённых дополнительных 11-адических кандидатов**, составляющие десять орбит, не допускают рационального подъёма к полной пятиформной системе G1(15,8). Достаточно трёх вспомогательных простых:

| Простой | Новых исключений | Осталось |
|---|---:|---:|
| 83 | 20 | 20 |
| 191 | 16 | 4 |
| 751 | 4 | 0 |

Все четыре известные рациональные точки D над x=0 и x=∞ проходят эти же проверки. Они соответствуют t=±1 и квадратам с повторениями. **Пустота C7 или всего D(Q) не утверждается.**

При принятии прежнего QC-покрытия полного пятиформного локуса это завершает исключение невырожденной девятки для (15,8), то есть последний вычислительный шаг фиксированного списка 127 G1-пар. Для окончательной сводки нужен аудит всей цепочки зависимостей, особенно происхождения QC-функций и теоретической оценки их хвостов. Новый отсев проверен отдельно; вычисление самих функций QC заново независимой реализацией не выполнялось. Общая задача для произвольных G1-пар и произвольных магических квадратов остаётся открытой.

## Модель и арифметика

```
D: y² = 44182609 x⁶ + 37608911 x⁴ + 47287151 x² + 4092529.
(a0,a2,a4,a6) = (4092529,47287151,37608911,44182609).
phi1(x,y)=(a6 x²,a6 y), phi2(x,y)=(a0/x²,a0 y/x³).
```

Работаем в исходных, не минимальных моделях:

```
E1: Y²=X³+37608911 X²+2089269703356959 X+7989037884942063852049,
P1=(21848689,286391046720), T1=(-4092529,0).
E2: Y²=X³+47287151 X²+153915558925919 X+740005399550399109169,
P2=(-18241391,87162492480), T2=(-44182609,0).
```

Насыщенные базисы E_i(Q)=Z P_i ⊕ (Z/2)T_i унаследованы из ранее проверенного input_basis.json. Модели и генераторы согласованы с картами. При11 порядки редукций P1 и P2 равны 14 и10.

Для каждого кандидата и каждого независимого выбора e1,e2∈{0,1} вычислены необходимые условия

```
phi_i(z) = m_i P_i + e_i T_i,
m1 mod (14·11⁶), m2 mod (10·11⁶).
```

Условие чётности из образа Jac(D) **не используется** в окончательном расчёте. Все четыре комбинации кручения разрешены. Поэтому результат не зависит от отдельного доказательства индекса образа якобиана.

Первый алгоритм поднимает коэффициент по одной 11-адической цифре, используя формальный параметр −X/Y. Второй вычисляет отношение формальных логарифмов точки и N_i P_i, затем независимо восстанавливает тот же класс коэффициента. Совпали все 160 сравнений: 40 точек × 2 фактора × 2 выбора кручения.

Это условия на целые 11-адические окрестности кандидатов. Исходные данные задают локальные x или 1/x по модулю 11²⁰; соответствующие y или y/x³ являются единицами, поэтому ветвь однозначно поднимается по Гензелю. Поднятые дифференциалы x dx/y и −dx/y интегральны в этих картах; деление на логарифм N_iP_i теряет одну цифру. Шесть используемых цифр лежат с запасом внутри известной точности. Для окончательного отсева достаточно информации по модулю11².

## Конечные поля

Для каждого вспомогательного простого l перечислены все точки D(F_l), включая x=0 и обе точки на бесконечности, допускающие исходные пять квадратностей. Используется t=(1+x)/(1−x), в однородной форме (A:B)=(1+x:1−x). На x=∞ берётся (A:B)=(1:−1). Проверяются

```
225 B²+64 A², (289/2)(A²+B²), 64 B²+225 A²,
(289/2)(A²+B²)−240 AB, (289/2)(A²+B²)+240 AB.
```

Нули разрешены. Никакого ограничения различности по модулю l не вводится. Для каждой такой точки определяются все возможные коэффициенты по редукциям P_i,T_i. Они сравниваются с 11-адическими классами по НОД соответствующих модулей.

| l | ord(P1 mod l) | ord(P2 mod l) | Общие модули для сравнения |
|---|---:|---:|---|
| 83 | 88 | 88 | (22,22) |
| 191 | 176 | 208 | (22,2) |
| 751 | 746 | 726 | (2,242) |

Несовпадение остатков исключает рациональную точку независимо от величины её координат или коэффициентов m_i. Это применение принципа решета Морделла–Вейля к двум эллиптическим образам. [Bruin–Stoll, The Mordell–Weil sieve](https://arxiv.org/abs/0906.1934).

## Что перепроверено и что унаследовано

1. dlog.py: коэффициенты всех40 точек, проверка остатка после обратного умножения, десять контрольных точек с заранее известными коэффициентами.
2. local_sieve.py: независимая от Sage реализация группового закона над конечными полями на стандартном Python; полный перебор локальных точек и квадратностей.
3. audit.py: другой алгоритм через степенной ряд формального логарифма; повтор конечных переборов средствами Sage на трёх решающих простых. Все локальные множества совпали. Проверена хорошая редукция. Все12 контролей известных точек прошли.
4. Повторно запущен прежний audit_strassmann.py: все24 проверки сохранённых QC-функций прошли. Это перепроверка изоляции корней **при сохранённых коэффициентах и оценках хвостов**, а не независимое получение этих функций/оценок.
5. Полнота насыщенных MW-базисов, теорема QC, вывод Ω_full из12 высот и корректность получения аналитических коэффициентов являются входами предыдущих этапов. Их нельзя заменить фактом совпадения точек при двух точностях. Архив содержит снимки основных входов для сквозного аудита.

Рабочий статус: **новый шаг решета завершён и перепроверен; сквозное закрытие (15,8) следует из него вместе с прежним сертификатом покрытия.** Полный список D(Q), включающий точки без пяти квадратностей, этим методом не определяется. Публикационная сводка автоматически не изменялась.

## Файлы и воспроизведение

Среда: Python с SageMath10.9; local_sieve.py требует только стандартную библиотеку Python. Запускать из каталога пакета:

```sh
DOT_SAGE=/tmp/codex-linear-sections-sage python3 dlog.py
python3 local_sieve.py
DOT_SAGE=/tmp/codex-linear-sections-sage python3 audit.py
DOT_SAGE=/tmp/codex-linear-sections-sage python3 prior_qc/audit_strassmann.py
```

- input_candidates.json — неизменённый снимок таблицы40 кандидатов;
- input_basis.json — предыдущие сертификаты базисов;
- dlog.json — все коэффициенты и модули;
- local_sieve.json — локальные множества, свидетели и исключения;
- audit.json — независимые проверки и контроли;
- prior_qc/ — прежние функции, данные изоляции, высот и локальных дисков;
- *_with_parity.json — предварительный этап, для окончательного вывода не нужен;
- SHA256SUMS — контрольные суммы пакета.
