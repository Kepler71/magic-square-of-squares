# LLL, поиск по высоте и модульное сито: проверенный пилот

Дата: 2026-09-11. Автор: Codex. Задача пользователя: проверить, помогает ли эта комбинация текущему поиску магического квадрата квадратов.

## Итог

Новых примеров с 7, 8 или 9 различными положительными квадратными клетками в этом пилоте нет. Воспроизведён контрольный пример из проекта: `(b,h)=(31,17)`, `f=23/17`, семь квадратных клеток.

На кривой с четырьмя используемыми генераторами сито оставляет **11 из 2500 состояний**, включая четыре исключения рационального отображения. Медианное время проверки сокращается примерно в **2,3 раза с учётом подготовки сита**, относительно той же области высот без сита. Это результат малого CPU-пилота, не прогноз для всего поиска.

Все **5843 отбрасывания из 6776 состояний** независимо подтверждены через точные рациональные координаты и модульные остатки. Список попаданий ≥7 совпадает до и после сита на каждой кривой. 20 исключений отображения сохранены ситом, но не разрешены самой исходной параметризацией.

## Что сравнивалось

Исходная модель скопирована из `corners/bremner_type.sage` проекта Claude; рабочий файл и текущие поиски Claude не изменялись.

1. Ящик коэффициентов исходных генераторов.
2. Такой же ящик после LLL-замены генераторов.
3. Столько же векторов, выбранных по малой канонической высоте после LLL.
4. Тот же список из пункта 3, предварительно отфильтрованный по простым модулям для цели **≥7 квадратных клеток**.

В ранге базиса 2 использован ящик `|n_i|≤5` (121 вектор), в ранге 3 — `≤3` (343), в ранге 4 — `≤2` (625). Каждый вектор сочетается со всеми точками кручения. Это отдельные уменьшенные тестовые области: новые точки относительно этого ящика могли уже встречаться в более широком поиске Claude.

Первые три кривые имеют квадратный центр; последние две — неквадратный. Последние две полезны только для промежуточной цели 7/8 квадратных клеток: девять при фиксированном неквадратном центре невозможны.

## Что изменил LLL и порядок по высоте

Для заданных генераторов `G` получены `Q=G U`, где `U` — целочисленная матрица с определителем ±1. Равенства точек проверены точно. Меняется базис той же порождённой подгруппы; её ранг не уменьшается. Высота комбинации оценивается формой `nᵀ H n`, после замены `H_new=Uᵀ H U`.

| Пара, условия | Макс. высота, старый ящик | Макс. высота, LLL-ящик | Макс. высота, список по высоте | Доп. допустимых f против тестового ящика |
|---|---:|---:|---:|---:|
| 31:17, TL/BR | 226,80 | 157,00 | 95,07 | 17 |
| 31:17, BL/TR | 213,46 | 213,46 | 104,64 | 14 |
| 17:7, TL/BR | 325,48 | 137,79 | 71,32 | 32 |
| 235:13, TL/BR | 653,76 | 284,32 | 136,07 | 64 |
| 235:41, BR/D | 426,48 | 162,31 | 68,61 | 190 |

Дополнительные `f` — новые только относительно малого исходного ящика данного теста, не новые решения задачи. Знаки `f` отождествляются; полная симметрия матриц не факторизована. При равном числе состояний число различных `f` может уменьшиться из-за повторений и симметрий. В последней строке максимальная битовая длина числителя/знаменателя допустимого `f` снизилась с 1310 до 257.

## Модель и безопасное сито

Для фиксированных `b,h` и рационального `f`:

```text
(h²+f²)/2       b²               (b²+2h²−f²)/2
b²+h²−f²       (b²+h²)/2         f²
(b²+f²)/2      h²               (2b²+h²−f²)/2
```

Все три строки, три столбца и две диагонали имеют сумму `3C`, где `C=(b²+h²)/2`. Это тождество; квадратность клеток — дополнительные условия.

Пять дополнительных выражений `TL,TR,BL,BR,D` имеют вид `a_i+b_i f²`. Для простого хорошей редукции, при определённом отображении, вычисляется верхняя оценка:

`upper_p = 3 + [C — квадрат в Q] + Σ_i [a_i+b_i f² — квадрат в F_p]`.

Если `upper_p<7`, кандидат не может иметь семь квадратных клеток над Q. Нулевой остаток считается квадратом. Полюсы и исключения отображения над F_p сохраняются. Выбираются первые восемь полезных хороших простых меньше 200; модули, на которых все точки разрешены, пропускаются. Простые, маски и свидетельствующий простой для каждого отбрасывания сохранены в `benchmark.json`.

Фильтр работает с конечными группами эллиптических кривых. Независимый аудит строит каждую исходную точку точно над Q, получает рациональное `f` и проверяет свидетельствующий простой напрямую — без конечного сложения точек, используемого фильтром. Во всех определённых точках отдельно проверены восемь магических сумм и число квадратных клеток.

## Статус утверждений и ограничения

- **Строгое алгебраическое основание:** магические суммы указанной матрицы; сохранение подгруппы при целочисленной замене с det ±1; необходимое условие квадратности по модулю хорошего простого при определённом отображении.
- **Точные конечные CAS-проверки:** равенства новых генераторов комбинациям старых, квадратность рациональных клеток, совпадение попаданий до/после сита и аудит всех 5843 отбрасываний в сохранённых областях. Это проверяемый вычислительный результат, не глобальная теорема о рациональных точках.
- **Численные данные:** матрицы высот и порядок кандидатов. Списки при 128 и 256 битах совпали; перечисление эллипсоида сверено с независимым декартовым перебором при том же численном пороге. Интервального сертификата точного глобального ограничения по высоте нет.
- **Неподтверждённая полнота:** исходные генераторы найдены с `proof=False`. Ни насыщенность полной группы Морделла–Вейля, ни глобальные ранги здесь не сертифицированы. «Ранг базиса» означает число используемых генераторов.
- **Исключительные точки:** исходное отображение возвращает `None` в четырёх состояниях на каждой кривой. Сито их не отбрасывает, однако для полного математического поиска их образы надо разобрать отдельно.
- **Нет вывода об отсутствии решения:** конечные области, пять выбранных кривых и две пары с неквадратным центром не покрывают всю задачу. Проектный класс `(-15,2,-30)` и его descent/lifting этим пилотом не закрыты.

## Следующий конкретный шаг для Claude

Применить экспериментальный фильтр сначала к более крупным областям кривых с 3–4 генераторами; для поиска именно девяти квадратов отбирать квадратные центры. Сохранить исходный алгоритм как контроль на одинаковом конечном списке. Замерять полный этап с построением сита и отдельно повторное использование таблиц; вести `ok/error/skip`, число состояний, различных f и исключений отображения. Не заменять текущий поиск автоматически по результату пяти кривых.

Для доказательного пути отдельно нужны сертификаты генераторов/насыщения и разбор исключительных точек. Для ускорения — кэширование таблиц и дальнейшая проверка окупаемости. Более широкий поиск может найти новые кандидаты, но успех не обещается.

## Файлы и воспроизведение

- `source_bremner_type.sage` — неизменённый снимок модели Claude.
- `probe.py`, `probe.json` — генераторы, модели кривых, LLL-матрицы и параметры отображений.
- `benchmark.py`, `benchmark.json` — четыре режима, точные векторы, маски, свидетели отбрасываний и результаты.
- `audit_and_timing.py`, `audit_and_timing.json` — независимый аудит и повторные замеры.
- `manifest.json` — версии и SHA-256 файлов.
- `RESULT.md` — эта записка.

Среда: SageMath 10.9, Python 3.14, CPU. Из распакованной папки с установленным Sage:

```sh
DOT_SAGE=/tmp/magic-square-sage /usr/bin/python probe.py
DOT_SAGE=/tmp/magic-square-sage /usr/bin/python benchmark.py
DOT_SAGE=/tmp/magic-square-sage /usr/bin/python audit_and_timing.py
```

На другой машине используйте Python из среды Sage. Для воспроизведения именно сохранённого списка генераторов можно пропустить `probe.py`. Повторный запуск перезапишет соответствующие JSON; исходные результаты сохранены в архиве.
